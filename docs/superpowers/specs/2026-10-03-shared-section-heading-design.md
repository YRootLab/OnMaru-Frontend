# 공통 섹션 헤더 디자인

## 목표

소리마루의 섹션 제목 표현을 기준으로 홈과 한옥마루의 최상위 섹션 헤더를 통일한다. 제목은 항상 위에, 설명과 보조 정보는 아래에 배치하며 카드·모달·히어로 내부 제목은 변경하지 않는다.

## 검토한 접근

1. 각 화면의 기존 스타일을 직접 수정하는 방식은 빠르지만 이후 크기와 그라디언트가 다시 달라질 가능성이 높다.
2. 소리마루 컴포넌트를 다른 기능에서 직접 가져오는 방식은 기능 간 의존 방향을 흐린다.
3. 공용 프레젠테이션 컴포넌트와 토큰을 만들고 각 기능에서 조합하는 방식은 중복을 줄이면서 기능 경계를 유지한다.

세 번째 방식을 사용한다.

## 시각 규칙

- 제목: `var(--font-hanok)`, `clamp(24px, 3.2vw, 36px)`, 700, `-0.045em`.
- 라이트 제목: `#211e19 → #403b35 → #6a6158` 텍스트 그라디언트.
- 다크 제목: `#ffffff → #d9d9d7 → #b0b8c1` 텍스트 그라디언트.
- 부제: 제목 바로 아래에 배치하고 기존 중립 회색 본문 토큰을 사용한다.
- 액션 링크: 기존 의미색과 상호작용을 유지하며 데스크톱에서는 헤더 우측에 둘 수 있다.
- 모바일: 제목과 부제·액션을 세로로 배치해 제목 위계와 줄바꿈을 보존한다.

## 구성

- 기능에 종속되지 않은 공통 `SectionHeading`을 shared presentation 경계에 둔다.
- 한옥마루의 기존 `SectionHeader`는 공통 컴포넌트를 조합하는 얇은 래퍼로 유지해 기존 호출부를 보존한다.
- 홈의 `JourneyDiscoveryFeed` 최상위 섹션 세 곳을 공통 컴포넌트로 교체한다.
- 소리마루는 공통 컴포넌트를 사용하도록 옮기되 현재 렌더링 결과는 유지한다.
- 카드 제목, 검색 히어로, 상세 모달, 결과 화면의 동적 제목은 범위에서 제외한다.

## 검증

- 공통 컴포넌트의 제목/부제 순서, 제목 태그, 액션 링크를 컴포넌트 테스트로 검증한다.
- 한옥마루와 홈의 대표 섹션이 공통 헤더를 렌더링하는지 확인한다.
- 라이트·다크 모드의 계산된 텍스트 그라디언트와 반응형 배치를 브라우저에서 확인한다.
- TypeScript, ESLint, 전체 Vitest와 관련 Playwright 시나리오를 실행한다.

## 함께 처리할 회귀

- 한옥 카드의 `도감 해설 보기` 버튼은 호버 시 위치가 변하지 않도록 하고 배경색 피드백만 유지한다.
- 카카오 지도 생성자는 잘못 바뀐 `kakao.maps.MapIcon`을 `kakao.maps.Map`으로 복원한다.
- 로컬 지도 SDK는 카카오 개발자 콘솔에 실행 origin(`http://localhost:3004`, 필요 시 `http://localhost:3008`)이 등록되어야 한다.
