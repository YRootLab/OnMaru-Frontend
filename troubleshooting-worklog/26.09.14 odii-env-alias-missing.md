# Odii 환경변수 alias 누락으로 오디오 화면 데이터가 비어 보인 문제

날짜: 2026-09-14

## 문제 상황

로컬 개발 화면에서 `/sorimaru` 오디 화면의 이야기 데이터가 갑자기 보이지 않았다.
다른 개발자 버전에서는 데이터가 보였고, 같은 화면 구조는 렌더링되지만 실제 이야기 목록만 비어 있었다.

## 오류명 또는 실패 증상

로컬 API route를 직접 호출했을 때 다음 응답이 내려왔다.

```json
{
  "response": {
    "header": {
      "resultCode": "9000",
      "resultMsg": "SORIMARU_API_KEY_MISSING"
    }
  },
  "degraded": true,
  "error": "SORIMARU_API_KEY가 설정되지 않았습니다"
}
```

즉 브라우저 UI 자체의 렌더링 오류가 아니라, 프론트의 `/api/sorimaru` 프록시가 API Key를 찾지 못해 빈 목록을 정상 응답처럼 내려준 상황이었다.

## 기존 구조나 방식의 한계

`.env.local`에는 서버 문서 기준으로 아래 이름들이 추가되어 있었다.

```env
ODII_API_URL=...
ODII_API_KEY=...
NEXT_PUBLIC_ODII_API_URL=...
NEXT_PUBLIC_ODII_API_KEY=...
```

하지만 기존 프론트 프록시는 예전 소리마루 내부 명칭만 찾고 있었다.

```ts
process.env.SORIMARU_API_KEY || process.env.NEXT_PUBLIC_SORIMARU_API_KEY
```

서비스 브랜드명은 `Sorimaru`, 공공데이터 API 상품명은 `Odii`라서 env naming이 갈라졌고,
이를 검증하는 로컬 hook이나 CI가 없어 누락이 화면의 빈 데이터로 늦게 발견됐다.

## 관련 코드 맥락

- `src/features/sorimaru-audio/api/sorimaru.service.ts`
  - `SorimaruService.proxyRequest()`가 Next.js API route `/api/sorimaru` 요청을 받아 한국관광공사 Odii API로 프록시한다.
  - `getApiKey()`가 env에서 service key를 읽고, 값이 없으면 외부 API를 호출하지 않고 degraded empty payload를 반환한다.
  - 문제 당시 `getApiKey()`가 `SORIMARU_API_KEY`, `NEXT_PUBLIC_SORIMARU_API_KEY`만 확인해 `ODII_API_KEY`를 인식하지 못했다.

- `src/app/api/sorimaru/route.ts`
  - thin controller로 `SorimaruService.proxyRequest(request)`만 호출한다.
  - 따라서 root cause는 route handler가 아니라 service의 env alias 해석 규칙이었다.

- `.env.local`
  - 실제 secret을 담는 로컬 파일이다.
  - git에 올라가면 안 되며, `.gitignore`로 제외되어야 한다.

## 검토한 선택지

1. `.env.local`에 `SORIMARU_API_KEY`를 추가한다.
2. 코드에서 `ODII_API_KEY`를 새 alias로 허용한다.
3. `SORIMARU_*` 이름을 전부 제거하고 `ODII_*`만 사용한다.
4. env contract 검사 스크립트를 만들어 hook과 CI에서 같은 규칙을 검증한다.

## 판단 기준

- 다른 개발자의 기존 `SORIMARU_*` env도 깨뜨리지 않을 것
- 서버 문서의 `ODII_*` env 이름도 그대로 사용할 수 있을 것
- `.env.local` 같은 secret 파일은 git에 올라가지 않을 것
- 같은 문제가 push 전에 로컬에서 잡히고, PR/merge 경로에서도 CI로 잡힐 것

## 최종 결정

기존 `SORIMARU_*` env를 유지하면서 `ODII_*` alias를 추가하고,
`.env.example`, `npm run check:env`, pre-push hook, GitHub Actions로 env contract를 명시적으로 검증한다.

## 해결 방식

1. `SorimaruService.getApiKey()`에서 다음 우선순위를 허용했다.

```ts
process.env.SORIMARU_API_KEY ||
process.env.NEXT_PUBLIC_SORIMARU_API_KEY ||
process.env.ODII_API_KEY ||
process.env.NEXT_PUBLIC_ODII_API_KEY
```

2. `SorimaruService.BASE_URL`도 기존 `SORIMARU_*`와 신규 `ODII_*` URL alias를 함께 읽도록 했다.

3. `src/features/sorimaru-audio/api/sorimaru.service.test.ts`를 추가해 `ODII_API_KEY`만 있어도 degraded 응답이 아니라 정상 upstream 호출을 수행하는지 검증했다.

4. `scripts/validate-env-contract.mjs`와 `npm run check:env`를 추가했다.
   이 스크립트는 Odii key alias 존재 여부, `.gitignore`의 env 규칙, tracked secret env 파일 여부를 검사한다.

5. `.gitignore`는 실제 env 파일을 계속 막되 `.env.example`만 허용하도록 정리했다.

```gitignore
.env*
!.env.example
```

6. `.githooks/pre-push`와 `.github/workflows/env-contract.yml`에서 같은 `npm run check:env`를 호출하게 했다.
