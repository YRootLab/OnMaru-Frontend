# 소리마루 섹션 리빌의 상향 복귀와 새로고침 flash 수정

## 날짜
2026-09-06

## 문제 상황
소리마루의 섹션 vessel animation은 아래로 스크롤할 때 새 섹션이 작게 준비됐다가 커지고, 위로 돌아갈 때 화면 하단으로 사라질 섹션은 다시 작아져야 한다. 그러나 최근 성능 수정 뒤 한 번 펼쳐진 섹션이 다시 접히지 않았고, 새로고침 시 현재 화면의 섹션도 축소 상태에서 커지는 motion을 재생할 수 있었다.

## 오류명 또는 실패 증상
- 하단에서 위로 스크롤해 섹션이 viewport 하단으로 빠져도 `scale: 1` 상태가 유지됐다.
- 새로고침/hydration의 초기 state가 `vessel`이어서 IntersectionObserver가 위치를 알려주기 전 현재 화면에 `scaleFrom: 0.92`, `opacity: 0.88`이 노출될 수 있었다.
- 첫 수정에서는 초기 보호에도 75% reveal 경계를 사용해, 화면 아래쪽 25%에 이미 보이는 섹션이 `y: 6px`인 vessel로 바뀌며 위치가 살짝 내려가는 것처럼 보였다.
- runtime exception은 없었으며 상태 전이 규칙이 요구 동작과 달라진 논리 오류였다.

## 기존 구조나 방식의 한계
- `hasRevealedRef`가 한 번 `true`가 되면 `getVesselRevealStage()`가 geometry와 관계없이 계속 `bloomed`를 반환했다.
- IntersectionObserver 첫 callback까지 초기 상태를 `vessel`로 두어 SSR/hydration 첫 화면의 시각 상태가 실제 scroll restoration 위치를 반영하지 못했다.
- “새로고침 당시 이미 본 섹션 보호”와 “현재 mount에서 새로 본 섹션의 상향 fold”가 하나의 `hasRevealed` flag에 섞여 있었다.

## 관련 코드 맥락

### `src/shared/components/animation/vesselRevealState.ts`
- 함수: `resolveVesselRevealState`.
- 책임: DOM이나 React와 무관하게 viewport geometry를 다음 `stage`와 mount-local `isReloadProtected`로 변환한다.
- 입력: 현재 stage, 최초 측정 여부, 초기 보호 여부, 교차 여부, section top, reveal boundary.
- 출력: `{ stage: 'vessel' | 'bloomed', isReloadProtected }`.
- 핵심 분기: 최초 측정은 실제 viewport 하단 위를 보호하고 아래를 접는다. 이후에는 보호된 섹션을 펼친 채 유지하고, 75% reveal 경계와 교차하면 펼치며, 그 하단으로 벗어나면 접고, viewport 위로 지난 경우 현재 상태를 유지한다.

### `src/shared/components/animation/VesselReveal.tsx`
- 책임: element 위치 측정, IntersectionObserver 수명, Framer Motion 출력만 담당한다.
- 초기 출력: SSR/hydration 기본 stage를 `bloomed`로 사용한다.
- 초기 보정: `useLayoutEffect`에서 paint 전에 실제 top을 동기 측정해 아래 섹션만 duration 0으로 `vessel`에 둔다.
- 경계 분리: reload 보호는 `window.innerHeight`, runtime reveal/fold는 기존 `exitThresholdRatio`를 사용한다.
- runtime 전이: observer callback에서 순수 상태 함수를 호출하며 stage가 실제로 바뀔 때만 React state를 갱신한다.
- 시각 계약: 기존 scale, y, opacity, radius, shadow, `0.85s` duration, easing은 변경하지 않았다.

### `src/shared/components/animation/README.md`
- 책임: 새로고침 보호, 하향 reveal, 상향 fold, reduced motion, API data와 animation 상태의 분리 원칙을 같은 모듈 디렉터리에서 설명한다.

## 검토한 선택지
1. `hasRevealedRef`를 단순 제거한다. 반려. 새로고침된 현재/위쪽 섹션도 하단 경계에서 다시 접힐 수 있다.
2. 전역 scroll listener로 방향을 매 프레임 추적한다. 반려. geometry만으로 구분 가능한 동작에 추가 listener와 잦은 계산이 생긴다.
3. section ID와 상태를 sessionStorage에 저장한다. 반려. ID가 없는 섹션이 있고 route/storage 수명 관리가 요구보다 크다.
4. 최초 위치만 mount-local 보호하고 이후 geometry 전이를 가역적으로 계산한다. 채택.

## 판단 기준
- 새로고침 현재 화면에 축소 flash나 reveal replay가 없어야 한다.
- 아래의 새 섹션만 하향 진입 animation을 실행해야 한다.
- 상향 복귀 시 하단으로 사라지는 섹션만 fold해야 한다.
- API loading과 무관하고 기존 UI/motion parameter를 변경하지 않아야 한다.
- scroll listener 없이 IntersectionObserver callback 횟수만큼만 상태를 계산해야 한다.

## 최종 결정
SSR 기본값을 `bloomed`로 바꾸고, `useLayoutEffect` 최초 측정으로 reload 보호 대상을 고정한 뒤, 순수 상태 모듈이 이후 하향 reveal과 상향 fold를 가역적으로 계산하도록 했다.

## 해결 방식
1. 기존 3개 상태 테스트를 6개 transition test로 교체하고 새 함수가 없어 모두 실패하는 RED를 확인했다.
2. `resolveVesselRevealState()`를 구현해 최초 보호, 초기 하단 fold, 진입 bloom, 하단 이탈 fold, 상단 통과 유지, reload 보호를 분리했다.
3. `VesselReveal` 초기 state를 `bloomed`로 변경하고 observer 등록 전 동기 위치 측정을 추가했다.
4. 영구 `hasRevealedRef`를 제거하고 mount-local `isReloadProtectedRef`만 유지했다.
5. animation 상태가 API data 완료 여부를 참조하지 않도록 README에 유지보수 경계를 기록했다.
6. 화면 아래쪽 25%에 걸린 섹션을 보호하는 회귀 테스트를 추가하고, 최초 보호 기준을 reveal 경계에서 실제 viewport 하단으로 교정했다.
