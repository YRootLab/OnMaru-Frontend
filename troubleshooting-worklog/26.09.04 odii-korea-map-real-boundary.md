# 오디 섹션3 지도를 실제 대한민국 경계 데이터로 교체

## 날짜
2026-09-04

## 문제 상황
`src/features/odii-audio/components/SoundConstellationSection.tsx`(오디 페이지에서 세 번째로 렌더되는 "전국 문화유산 소리 지도" 섹션)가 실제 지도처럼 안 보인다는 지적. 레퍼런스로 받은 이미지는 실제 한국 지도 실루엣 위에 지역 캡슐이 지리적으로 배치된 형태였는데, 기존 구현은 임의로 그린 blob 모양 SVG path(`MAP_PATH` 상수, 손으로 만든 좌표) 위에 `REGIONS` 배열의 수동 x/y % 좌표로 pill 버튼을 흩뿌려놓은 것이어서 "지도"로 인식이 안 됨.

## 오류명 또는 실패 증상
정확한 런타임 에러는 아니고 두 가지 실측 트러블슈팅이 있었음.

1. **제주 지역이 안 보이는 것처럼 보임**: 지도 교체 직후 스크린샷에서 "제주 4" 라벨만 있고 섬 모양이 전혀 안 보여서 렌더링 버그로 의심.
2. **호버 시 지도 위 라벨 태그가 이동**: 지역 라벨을 호버하면 위치가 튀는 것처럼 보임(사용자 리포트: "호버하면 태그가 막 이동하네").

## 기존 구조나 방식의 한계
- `SoundConstellationSection.tsx`의 `MAP_PATH`는 실제 좌표계와 무관한 임의 블롭이라 지리적으로 읽히지 않음.
- `REGIONS` 배열은 지역마다 `color` 필드(`#f84e76`, `#6b9b80`, `#c08c53`...)를 따로 갖고 있어 무지개색으로 렌더 — 페르소나 스타일 가이드(`agents/fe_engineer.md`)의 "형형색색 뱃지 지양" 원칙과도 어긋남.
- 좌표가 수작업이라 지역을 늘리거나(제주 등) 정밀도를 높이는 게 불가능.

## 관련 코드 맥락

### 1) 실제 경계 데이터 추출 스크립트 — `scratchpad/extract_map.py`
`statgarten/maps`(MIT License, 통계청 SGIS API 기반 대한민국 행정경계 SVG/GeoJSON 오픈소스) 레포를 클론해서 `svg/simple/전국_시도_경계.svg`(17개 시도, 시도당 `<path d="..." id="서울특별시"/>` 형태로 이미 단순화된 경계)를 파싱하는 스크립트.

- 정규식 `<path\s+([^>]*?)/>`로 각 `<path>` 태그를 찾고, 그 안에서 `d=`와 `id=`를 속성 순서와 무관하게 따로 추출(`fill-rule="evenodd"`가 `d`와 `id` 사이에 끼어있는 시도가 있어서 처음엔 매칭이 8개만 잡히는 버그가 있었음 → 속성 순서 의존 정규식을 버리고 태그 전체를 잡은 뒤 재검색하는 방식으로 수정).
- `GROUPS` 딕셔너리로 17개 시도를 기존 8개 그룹(서울·경기·인천 / 강원 / 충북 / 충남·대전·세종 / 전북 / 전남·광주 / 경북·대구 / 경남·부산·울산)에 제주를 더한 9개로 병합. 시도별 `d`를 문자열로 이어 붙여 하나의 `<path>`로 렌더할 수 있게 함.
- `split_subpaths`/`subpath_points`로 각 시도의 `d`를 `M...Z` 단위 서브패스(섬 단위)로 쪼갠 뒤, `MIN_FEATURE_SIZE = 2.5`(viewBox 800×759 기준 단위) 미만인 서브패스는 화면에서 사실상 안 보이는 디지털화 노이즈로 판단해 제거. 백령도·울릉도/독도처럼 실제 크기가 있는 섬은 threshold를 넘어서 그대로 유지됨(정치적으로도 독도를 빼면 안 되는 지점이라 threshold를 더 올리지 않기로 판단).
- 남은 서브패스 좌표를 소수점 1자리로 반올림해 파일 크기를 줄이고, 그룹 전체 좌표의 산술 평균을 `centroid`로 계산해 라벨 위치 기준으로 사용.
- 최종적으로 `src/features/odii-audio/data/koreaMapPaths.ts`(약 136KB, `KOREA_MAP_VIEWBOX = "0 0 800 759"`, `KOREA_REGION_PATHS: KoreaRegionPath[]`)를 생성.

### 2) 지도 컴포넌트 — `SoundConstellationSection.tsx`
- `KOREA_REGION_PATHS`를 순회하며 `<motion.path>`로 각 권역을 그림. `selectedRegionId`와 같으면 `fill: '#f84e76'`, 아니면 모노톤(`#fffdf9`)로 `animate`. 색은 선택 여부로만 갈리고 지역별 고정 색은 없앰.
- `getRegionStories(stories, region)`: `region.keywords`(예: 서울 그룹은 `["서울","경기","인천"]`)가 스토리의 `locationName/title/audioTitle/category`를 이어붙인 텍스트에 포함되는지로 지역 매칭. 매칭이 하나도 없으면 `stories.slice(0, 4)`로 폴백 — 지금 목데이터엔 실제 지역 필드가 없어서 쓰는 임시 방편.

## 검토한 선택지
1. 기존 blob path를 유지하고 좌표만 수동으로 다듬는다 — 반려. "이런 형식 별로"라는 지적의 원인 자체를 안 건드림.
2. 레퍼런스처럼 풀스크린 "지역선택" 모달로 전환한다 — 반려. 이건 전역 위치선택기 패턴이라 인라인 지도+리스트가 이미 더 적은 단계로 풀고 있는 탐색 흐름을 오히려 늘림.
3. 오픈소스 실제 경계 데이터를 가져와 프로그래밍적으로 9개 권역으로 병합한다 — **채택**.
4. 기존 `AllStoriesModal`(다크 테마 전체 아카이브 모달)을 지역 필터를 추가해서 재사용한다 — 반려. 톤이 이 섹션의 밝은 팔레트와 안 맞고, 지역 필터 자체가 없어서 관련 없는 컴포넌트까지 손대야 함(비침해 원칙 위반).

## 판단 기준
- 지리적으로 실제로 읽히는 형태여야 한다(핵심 불만 해소).
- 수정 범위는 타겟 섹션에 한정하고 다른 컴포넌트는 건드리지 않는다.
- 페르소나 스타일 가이드: 모노톤 베이스 + 선택 시에만 accent 컬러, 컬러풀한 뱃지 지양.
- 데이터 출처는 라이선스(MIT) 확인 후 사용.

## 최종 결정
`statgarten/maps`의 시도 경계 SVG를 9개 권역으로 병합·정제해 `koreaMapPaths.ts`로 굽고, 지도 컴포넌트가 이를 순수 SVG path로 렌더하도록 재작성. 인라인 지도+리스트 구조는 유지, 모달 도입은 안 함.

## 해결 방식
1. `git clone statgarten/maps` 후 `LICENSE`(MIT) 확인.
2. `extract_map.py`로 17개 시도 path 파싱 → 9개 그룹 병합 → 노이즈 섬 필터링 → centroid 계산 → `koreaMapPaths.ts` export.
3. `SoundConstellationSection.tsx`를 재작성해 실제 지도 path 렌더 + 선택 상태에 따른 accent color 애니메이션 적용.
4. **제주 미표시 의심 해결**: `curl`로 SSR HTML을 떠서 제주 path의 `d`가 실제로 존재하는지 먼저 확인(존재함) → Chrome headless를 `--remote-debugging-port`로 띄우고 CDP(`Runtime.evaluate` + `getBoundingClientRect`)로 라이브 DOM에서 직접 좌표·크기·`computedFill`을 찍음 → `rect: {w: 59, h: 33}`, `fill: #fffdf9`, `visibility: visible`로 정상 렌더링 확인. 원인은 버그가 아니라 제주 섬 자체가 작아서 그 위에 얹힌 라벨 pill이 섬을 거의 다 가리는 착시였음.
5. **호버 이동 버그 해결**: 라벨을 `<motion.button>` 하나에 Tailwind `-translate-x-1/2 -translate-y-1/2`(중앙 정렬)와 `whileHover={{scale:1.06}}`를 같이 걸어뒀던 게 원인. framer-motion이 `transform`을 자체적으로 소유하면서 hover 시 Tailwind의 translate 값을 덮어써 위치가 튀었음. 위치 고정은 순수 CSS `<div>` wrapper로 분리하고, `<motion.button>`은 그 안에서 scale만 담당하도록 구조 변경 → CDP로 마우스를 실제로 올려 `getBoundingClientRect` 중심점이 hover 전후로 `dx=0.00, dy=0.00`인 것을 확인. (이후 사용자가 hover 확대 자체를 없애달라고 해서 `motion.button` → 일반 `<button>`으로 되돌리고 `whileHover`/`whileTap` 제거.)
6. 이후 여러 라운드 UX 피드백 반영: `SELECTED REGION` 에디토리얼 라벨 제거, 섹션을 감싸던 바깥 배경 카드(`bg-[#fbf8f2] rounded-[28px]`) 제거, 헤더를 "오늘, 여기에서" 섹션과 동일한 포맷(그라디언트 타이틀 + 설명 + 우측 통계 텍스트)으로 통일, 미니 플레이어와 중복되는 "OO 이야기 하나 듣기" CTA 버튼 제거, 오른쪽 리스트에 `VISIBLE_STORY_COUNT = 6` 초과 시 패널 내부에서 펼쳐지는 "더보기" 토글 추가(지역 전환 시 렌더 중 `expandedForRegion !== selectedRegionId` 비교로 자동 리셋 — `useEffect` 안에서 `setState`하면 린트 에러(`react-hooks/set-state-in-effect`)가 나서 렌더 중 조정 패턴으로 변경), 선택 지역 글로우 크기와 지도 배경색(`#f4efe7` → `#f8f4ec`) 밸런스 조정(처음엔 2단 drop-shadow로 과하게 키웠다가 "색이 너무 많다"는 피드백에 단일 `drop-shadow(0 8px 20px rgba(248,78,118,0.3))`로 되돌림), 라벨 버튼 `outline-none` 추가.

## 결과
- 실제 대한민국 지도 실루엣 기반의 인터랙티브 지도 완성. `npx tsc --noEmit`, `npx eslint`, `npx vitest run src/features/odii-audio`(28 tests) 전부 통과.
- Chrome headless 스크린샷(데스크톱 1280px / 모바일 390px)과 CDP 클릭 시뮬레이션으로 실제 인터랙션(지역 클릭 → 하이라이트 이동 → 우측 리스트 갱신) 확인.
- 남은 과제: `getRegionStories`의 키워드 substring 매칭은 임시방편. 실 API가 스토리마다 실제 지역 코드/이름 필드를 내려주기 시작하면, 이 함수만 "텍스트 키워드 매칭"에서 "실제 지역 필드 == 9개 그룹 매핑"으로 교체하면 됨 — 리스트 UI(더보기, 구분선 등)는 그대로 재사용 가능.
