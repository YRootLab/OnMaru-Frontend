# 한옥 전국지도 미동작과 회색 배경 수정

## 날짜
2026-09-06

## 문제 상황
한옥도감의 `전국 지도` 영역이 Kakao 지도를 표시하지 못했고, 페이지 Root와 body를 흰색으로 바꾼 뒤에도 한옥 화면 일부가 회색 또는 옅은 유색 면으로 보였다. 기존 지도 UI, 섹션 flow, typography, animation은 유지해야 했다.

## 실패 증상
- `.env.local`에는 ODII/TourAPI 설정만 있고 지도 컴포넌트가 읽는 `NEXT_PUBLIC_KAKAO_MAP_KEY`가 없었다.
- `HanokInteractiveMapFrame`은 key가 없으면 SDK `<Script>`를 만들지 않고 환경 변수 누락 오류를 표시하도록 되어 있었다.
- `/hanok`의 `Root`와 `body`는 흰색이었지만 공통 `PageContainer`의 상단 66px padding은 전역 app background가 비쳤다.
- viewport activation 전 `HanokMap` placeholder는 따뜻한 반투명색, dynamic component의 frame/loading overlay는 옅은 청회색이었다. 지도가 실패하거나 아직 활성화되지 않으면 이 면이 오래 노출됐다.

## 원인

### 1. 환경 변수 계약 불일치
사용 가능한 로컬 값의 이름은 `KAKAO_MAP_KEY`였지만 클라이언트 코드는 `NEXT_PUBLIC_KAKAO_MAP_KEY`만 참조했다. Next.js client bundle은 `NEXT_PUBLIC_` 변수를 정적으로 치환하므로 서버형 이름을 component에서 직접 읽는 방식으로는 해결할 수 없다.

### 2. 흰색 적용 경계가 route Root보다 좁음
`PageContainer`가 한옥 Root 바깥에서 padding과 최소 높이를 소유한다. 따라서 child Root와 body만 흰색이어도 공통 container 자체가 투명하면 전역 `--color-bg-app`이 상단/측면에서 보일 수 있다.

### 3. 지연 로딩 상태의 별도 surface
전국 지도는 `useViewportActivation({ rootMargin: '800px 0px' })` 뒤 dynamic import와 Kakao SDK load를 순서대로 수행한다. 이 비차단 전략은 유지해야 하지만, 두 단계의 placeholder가 페이지 흰색과 다른 배경을 사용했다.

## 해결 방식
1. `resolveKakaoMapKey()`를 추가해 공개형 key를 우선하고 서버형 key를 fallback으로 받게 했다.
2. `next.config.ts`에서 정규화된 값을 `NEXT_PUBLIC_KAKAO_MAP_KEY`로 주입했다. component와 공용 map hook의 기존 계약은 유지했다.
3. 제공받은 key는 Git에 추적되지 않는 `.env.local`의 `KAKAO_MAP_KEY`로 저장했다.
4. `getPageContainerPresentation()`으로 route별 container 표현을 분리하고 `/hanok`에만 `#ffffff`를 적용했다. 기존 full-bleed route 판정은 그대로 유지했다.
5. 한옥 지도 viewport placeholder, interactive frame, SDK loading/error overlay의 배경을 흰색으로 맞췄다. 지도 내부 controls, marker, border, 높이, radius, transition은 변경하지 않았다.
6. 후속 확인에서 theme global style의 `body background-color: #fafafa`와 0.3초 transition이 남아 있음을 확인했다. `data-page-surface="hanok"` 표식을 기준으로 `html/body`를 흰색으로 고정하고 한옥 route에서 body 배경 transition을 제외해 client navigation이나 style 재주입 뒤 회색 canvas가 다시 드러나는 경로를 막았다.

## 검증
- 실패 우선 unit test: resolver와 route presentation module이 없을 때 두 suite가 module-not-found로 실패하는 것을 확인했다.
- 수정 후 대상 unit test: 3 files, 6 tests 통과.
- 전체 unit test: 25 files, 84 tests 통과.
- TypeScript 검사 통과.
- 대상 ESLint 통과.
- Next.js 16.2.10 production build 통과; `/hanok`과 `/map` 모두 static prerender 유지.
- 제공된 key와 `Referer: http://localhost:3000/`으로 Kakao Maps SDK를 요청해 HTTP 200, SDK 본문, invalid/unauthorized 문자열 없음 확인.
- 재시작한 개발 서버에서 `/hanok` HTTP 200, 약 63ms, 서버 HTML에 흰색 background rule 포함 확인.

## 남은 검증 범위
자동화 browser instance가 연결되지 않아 실제 tile paint, marker cluster, 지역 chip 조작을 screenshot으로 검증하지는 못했다. SDK 네트워크와 설정 경로는 정상이며, 실제 브라우저에서 계속 실패한다면 Kakao Developers의 Web 플랫폼 domain 등록과 DevTools console의 SDK 오류를 다음 진단 입력으로 사용한다.

## 보안 및 운영 메모
`.env.local`은 `.gitignore`의 `.env*` 규칙으로 계속 제외된다. Kakao JavaScript key는 브라우저에 전달되는 식별자이므로 비밀 저장에 의존하지 않고 허용 Web origin을 Kakao Developers에서 제한한다. TourAPI/ODII server credential의 처리 방식과는 구분한다.
